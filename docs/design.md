# 设计说明：为什么不是「一键清理」

这份文档解释技能里的每个关键取舍。如果你只想用，读 README 就够了。

## 1. 为什么不直接告诉用户「删这 5 个文件夹」

因为「删哪个文件夹」高度依赖机器状态：

- `AppData\Local\Temp` 在有人机器上 2 GB，在服务器上 200 MB。
- `NVIDIA\DXCache` 可能 200 MB 也可能 10 GB（取决于玩过多少游戏）。
- 同一个 `Program Files\Tencent`，可能是腾讯会议，也可能是游戏组件。

所以技能不预置「垃圾路径清单」，而是**先扫描再判断**。分类表给的是判据（这是缓存吗？删了会怎样？），不是路径。

## 2. 为什么坚持四分类，而不是「安全 / 危险」二分

二分法会漏掉最重要的一类：**不能删但可以缩小**。

`hiberfil.sys` 6.3 GB——按二分法属于「危险，别动」，用户就永远省不下这 3 GB。实际上 `powercfg /h /type reduced` 能在保留快速启动的前提下砍掉一半。

同理 `WinSxS` 11.6 GB：不能删，但 `DISM /StartComponentCleanup /ResetBase` 能安全回收 2–4 GB。

所以第四类是「用系统命令调整」，和「删除」是两种动作。

## 3. 迁移为什么优先 junction，而不是全搬 + 重装

假设用户 200 GB 软件都装在 C 盘。重装方案要：

1. 记录每个软件的授权状态、插件、配置；
2. 逐个卸载重装；
3. 修复丢失的关联与路径。

而 junction 是文件系统层的重定向：路径字符串完全不变，软件读到的还是 `C:\Users\...\AppData\Local\Arduino15`，实际数据在 D 盘。**零配置、零重装、可随时撤销**（删链接搬回来）。

代价是：如果软件的更新器在升级时「删目录 + 重建」，junction 会被覆盖成真目录，数据看起来"消失"（其实在 D 盘）。所以技能里给了硬判据：

> 该目录的更新器会不会在升级时删除并重建整个目录？会 → 必须重装；不会 → 可以 junction。

浏览器、WPS、剪映属于前者；缓存、工具链、用户数据属于后者。

## 4. 为什么桌面必须走注册表，不能 junction

实测：对 `C:\Users\<user>\Desktop` 执行 `Rename-Item` 会返回「访问被拒绝」——Explorer 持有该目录的句柄。既然不能改名/删除，就无法「搬走内容 + 原地建链接」。

官方「属性 → 位置 → 移动」走的是注册表 `User Shell Folders\Desktop`，Explorer 重启后生效，等价于告诉系统「桌面在 D 盘」。这是唯一不破坏特殊文件夹语义的做法。

## 5. 为什么脚本注释是纯 ASCII

PowerShell 5.1（Windows 10 默认）在读取**无 BOM 的 UTF-8 脚本**时按 ANSI 解码。中文注释会变成乱码，字符串里的引号可能被吃掉，直接导致 `ParserError` 而脚本一行都没执行。

两种解法：写文件时加 BOM，或脚本里只用 ASCII。技能选了后者——因为仓库被 clone 后编辑器可能悄悄改编码，而 ASCII 永远不会坏。

## 6. 为什么扫描器自己写，不用 `Get-ChildItem -Recurse`

`Get-ChildItem` 递归 60 万文件在 PS 5.1 下要跑十几分钟，而且遇到符号链接会跟进去。

技能里的 `scan-drive.ps1` 用 C# 编译一段枚举器：单遍遍历、跳过重解析点、在内存里按 parent 累加，60 万文件约 12 秒。同时它就是唯一一次遍历，不会出现「扫三遍对不上」的问题。

关键细节：**输出里根节点那一行才是总量**。把所有行相加会重复计算每一层父目录——这个错误在开发时真的发生过，把 136 GB 算成了 998 GB。

## 7. 为什么先出报告、再等确认

「清理磁盘」是不可逆操作，而小白用户无法判断「`Windows\Installer` 能不能删」。技能把不可逆决策交还给用户，只提供**可读的判断依据**：

> 「C:\SWSetup 1.82 GB，惠普出厂驱动包，系统有恢复分区可以重装，删了不影响使用」

用户看到这句话才有能力说「删」。这也是为什么 SKILL.md 里专门有一节「汇报给小白的话术」。

## 8. 为什么不做分区调整

把 D 盘空间挪给 C 盘听起来更彻底，但：

- 需要第三方分区工具（Windows 自带磁盘管理只能向右扩展相邻未分配空间）；
- 操作中断电 = 分区表损坏 = 数据全丢；
- 对小白是高风险动作。

技能只给建议，不代做。真正的建议写在报告里：**如果 C 盘反复告急，那是容量规划问题，不是清理问题**。

## 9. 已知不足

- 只处理「空间去哪了」，不处理「重复文件」——那是另一个问题域。
- 不识别 Windows 之外的操作系统。
- 游戏去留、个人文件去留，技能只提供证据（体积、最近修改时间），不替用户决定。
